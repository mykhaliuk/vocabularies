Media affordance

Two surfaces: the compose media picker across every state and both entitlement tiers, and the video moment in the feed. Audio is for everyone; video is premium. The server stays the gate — this design only makes the gate honest and gentle.

The three open questions, answered

Q1 · one control or two
Tier decides — and that is the point.

Premium: one combined “voice or video” control; kind is inferred from the file. Nothing to choose, one tap fewer.
Non-premium: two controls — voice plus a visible locked video. The lock needs a body of its own to sit on; folded into a combined control the gate would only appear as a failure.

Q2 · locked video
A muted chip with a lock, tap opens one small sheet.

No hover anywhere — the state is legible at rest (sunk fill, hairline border, --ink-3, trailing Lock). Tap → a bottom sheet that names premium and offers one CTA. The audio path stays open right beside it.

Q3 · feed video card
No poster card. One line, then it opens.

Collapsed, the video keeps the audio player's exact rhythm — play · strip · duration. Tap expands a framed player inline; portrait and landscape both fit without swallowing the entry. The word stays the loudest thing on screen.

1 · Compose media picker

The affordance layer

Sits in the existing add-chip row (meaning · story · … · collection), so media never gets its own toolbar. The panel underneath is the approved upload dropzone — only the affordance layer changes with tier.

2 · Feed video card

Quiet by default, opens on tap

The collapsed row is 36px tall inside a 44px tap area — the same block the audio player occupies, so a mixed feed keeps one rhythm. Poster comes from the 720p derivative (poster.jpg): cover in the collapsed strip, contain in the expanded frame so faces are never cropped. Short edge stays 720, never upscaled.

4 · Rules the build must keep

  • The server is the gate. Every locked affordance is presentation only; a 403 VIDEO_UPLOAD_FORBIDDEN or a post-probe failed row must always land in the failed state above, never in a dead end.
  • Limits mirrored client-side, best effort: video ≤ 20 s, audio ≤ 180 s, ≤ 250 MB. Client rejection reads exactly like server rejection.
  • Kind inference: video/* MIME first, extension as fallback (mov · mp4 · webm · mkv · 3gp) — never the filename alone.
  • Tokens only. Accent for all media chrome is --secondary (blue = media, so audio and video read as siblings); the poster frame is --surface-sunk so imagery reads as content. Rose stays with the primary action and the upsell icon. Radii --r-sm (strip, chips) · --r-card (expanded frame) · --r-xl (sheet). Failure uses --danger / --danger-bg. Overlay fills are color-mix of --ink — no raw hex.
  • Icons (lucide-vue-next): Mic · Video · Lock · Upload · Loader · Play · ChevronUp · Check · Repeat · RefreshCw · AlertCircle · Paperclip. 44px minimum tap target everywhere, including the collapse control and the collapsed row.
  • Motion: 120/200/320ms on --ease-out. Progress is a linear width transition, not a loop. The poster shimmer and the spinner are the only repeating animations, both dropped under prefers-reduced-motion (the state stays readable from the label alone).
  • Copy: sentence case, one breath, no error codes, no exclamation. Never “upgrade now” — “see premium”.
  • Sheet footer honors --safe-bottom; the sheet backdrop uses --scrim.

5 · Still needs product

  • Where see premium goes — no plans screen exists in the prototype; the sheet CTA is a stub, and the sheet carries no price.
  • Whether the premium combined control should still mention video for a free user who has the combined variant forced (currently: lock badge + a note in the panel).
  • No trim / crop / thumbnail-pick UI in v0 — the 20s limit is a hard reject, not a trimmer. Confirm that's acceptable for launch.
